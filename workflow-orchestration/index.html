Who owns the next decision?

A provider response, a deadline and a customer correction can arrive in any order. The workflow must decide which event still applies to the pending operation.

Event choreography

Consumers coordinate through events

Each consumer persists its progress and correlates events. The team must decide which consumer resolves a late result or a competing timeout.

Results and deadlines return to one owner. Its code checks the operation ID, records the outcome and decides what can run next.

What can replay safely?

A replacement worker runs the handler again. A completed journal entry supplies its earlier result. An unfinished external step can execute again.

What an on-call engineer needs

Three recovery questions belong in the runbook before a long-running workflow goes into production.

Which deployment can resume it?

Keep replay-compatible code available for in-flight invocations. Drain an older worker after its pinned invocations finish.

Which system has the answer?

Inspect the journal for completed steps, the original vendor for an ambiguous operation, and the outbox for pending delivery.

Which state must be restored?

Back up workflow history and SQL revisions at their respective boundaries. Rehearse restoration, replay and receiver deduplication.

↳Write the acceptance check first. Interrupt the operation, resume it, and prove how many times the external effect occurred.
